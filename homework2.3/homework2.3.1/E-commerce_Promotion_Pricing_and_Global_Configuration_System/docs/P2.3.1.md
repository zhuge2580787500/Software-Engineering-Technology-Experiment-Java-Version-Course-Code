# 第二讲实践任务3.1：电商促销计价与全局配置系统
**📍 考察模式：策略模式 (Strategy) + 单例模式 (Singleton)**

**背景描述：**
某电商平台需要开发一个订单计价模块。平台存在多种不同的促销折扣规则，且未来可能会不断增加新的规则。同时，系统需要一个全局唯一的配置管理器来读取平台的全局参数（如：平台名称、全局基础税率）。

**具体要求：**
1. **应用单例模式**：设计一个 `GlobalConfigManager`（全局配置管理器）类，确保在整个系统中只能创建一个实例。
    * 该类内部包含属性：`platformName`（平台名，如"天天购物"）和 `taxRate`（税率，如 0.05）。
    * 提供获取实例的全局访问点（请考虑线程安全的单例实现方式，如双重检查锁或静态内部类）。
2. **应用策略模式**：设计订单折扣接口 `DiscountStrategy`，包含方法 `double calculate(double originalPrice)`。
3. **实现具体策略**：
    * `NoDiscountStrategy`：无折扣，原价返回。
    * `PercentageDiscountStrategy`：打折策略（按构造器传入的比例打折，如8折）。
    * `ThresholdDiscountStrategy`：满减策略（如满500减50）。
4. **上下文类**：设计 `Order`（订单）类，包含订单总金额和绑定的 `DiscountStrategy`。提供一个 `checkout()` 结账方法。
    * 结账方法中，先使用策略模式算出折后价，再从 `GlobalConfigManager` 单例中获取税率算出含税最终价并打印。

**测试流程：**
在 `Main` 方法中，验证单例的唯一性；创建不同策略的订单，验证计价逻辑是否正确解耦。
