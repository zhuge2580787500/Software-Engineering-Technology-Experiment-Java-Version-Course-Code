# 第二讲实践任务3.3：全格式媒体播放器集成系统
**📍 考察模式：工厂方法模式 (Factory Method) + 适配器模式 (Adapter)**

**背景描述：**
某公司拥有一个标准的媒体播放器项目，目前只支持播放 MP3 格式文件。为了拓展业务，公司购买了一个第三方的、闭源的高级音频库（支持播放 FLAC 和 WAV 格式），但这个第三方库的接口与公司现有的标准接口完全不兼容。同时，系统需要一种优雅的方式来根据文件后缀名创建不同的播放器实例。

**具体要求：**
1. **标准接口定义**：定义公司现有的标准接口 `MediaPlayer`，包含方法 `void play(String audioType, String fileName)`。
2. **基础实现**：编写 `Mp3Player` 实现 `MediaPlayer` 接口。
3. **第三方库（模拟闭源）**：
    * 存在接口 `AdvancedAudioPlayer`，包含方法 `void playFlac(String fileName)` 和 `void playWav(String fileName)`。
    * 存在实现类 `VlcPlayer`（实现了 `AdvancedAudioPlayer`）。
4. **应用适配器模式**：编写 `MediaAdapter` 类实现 `MediaPlayer` 接口。
    * 该适配器内部持有一个 `AdvancedAudioPlayer` 的实例。
    * 当客户端调用标准 `play` 方法且格式为 FLAC/WAV 时，适配器负责将请求翻译（转换）并委托给 `AdvancedAudioPlayer` 实例的相应方法。
5. **应用工厂模式**：
    * 编写 `MediaPlayerFactory` 工厂类，提供一个静态方法 `MediaPlayer getPlayer(String audioType)`。
    * 如果传入 "mp3"，工厂返回 `Mp3Player` 实例；如果传入 "flac" 或 "wav"，工厂返回装载了 `VlcPlayer` 的 `MediaAdapter` 实例。

**测试流程：**
在 `Main` 方法中，客户端**不直接 `new` 任何具体的播放器**，只通过 `MediaPlayerFactory.getPlayer(后缀名)` 获取播放器对象。然后分别尝试播放 `song.mp3`、`lossless.flac` 和 `record.wav`，验证适配器是否成功将第三方接口转换为了标准接口供客户端无缝使用。
